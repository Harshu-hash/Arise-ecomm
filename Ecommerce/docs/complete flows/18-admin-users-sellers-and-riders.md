# Admin Users, Sellers, and Riders

## What Is This?

Admins manage all people on the platform — customers, sellers, and delivery partners. This includes approving new applications, viewing profiles, and monitoring activity. This document covers all user management features.

---

## Who Uses This?

**Platform administrators** managing users across the platform.

---

## What Can You Do?

- View and search all customers
- Approve or reject seller applications
- Approve or reject delivery partner applications
- View active sellers and their locations
- Monitor active delivery fleet
- View detailed profiles for any user

---

## Customer Management

### Customer list

- All registered customers
- Search by name, phone, or email
- See registration date and order count

### Customer detail

Click a customer to see:

- Profile information (name, phone, email)
- Order history (all past orders)
- Wallet balance and transactions
- Support tickets
- Addresses saved

### What admin can do

- View customer data (for support and dispute resolution)
- Cannot place orders on behalf of customers
- Cannot directly change wallet balance without going through finance tools

---

## Seller Management

### Pending sellers

New seller applications waiting for approval:

1. Admin sees list of pending applications
2. Admin opens application to review:
   - Shop name and description
   - Contact details
   - Documents (if uploaded)
3. Admin **approves** or **rejects**
4. Seller is notified of the decision

### Active sellers

All approved and operating sellers:

- Shop name, location, contact
- Number of products listed
- Order count and revenue
- Online/offline status

### Seller detail

- Full shop profile
- Product list
- Order history
- Earnings and wallet
- Bank details

### Seller locations map

A map showing all active seller shops as pins. Useful for:

- Understanding geographic coverage
- Identifying gaps in service areas
- Planning expansion

---

## Delivery Partner Management

### Pending riders

New rider applications waiting for approval:

1. Admin sees list of pending applications
2. Admin opens application to review:
   - Personal details
   - Uploaded documents (ID, vehicle registration, photo)
   - Vehicle information
   - Bank details
3. Admin **approves** or **rejects**
4. Rider is notified of the decision

### Active riders

All approved delivery partners:

- Name, phone, vehicle type
- Online/offline status
- Total deliveries completed
- Current cash in hand (COD)
- Earnings

### Active fleet

Real-time view of all online riders:

- Who is online right now
- Who is on an active delivery
- Who is available for new jobs
- Location on map

---

## General User Management

A unified search to find any user on the platform by name, phone, or email. Opens their profile regardless of role.

---

## Approval Best Practices

### Sellers

- Verify shop name and location are real
- Check that contact details are valid
- Ensure shop is in a serviceable area
- Reject incomplete or suspicious applications

### Riders

- Verify government ID is valid and matches the applicant
- Check vehicle registration
- Ensure bank details are complete
- Reject forged or expired documents

---

## What Happens Behind the Scenes

- Approval changes the user's status from "pending" to "active"
- Approved sellers can immediately list products and receive orders
- Approved riders can go online and accept delivery jobs
- Rejected users are notified and cannot access role-specific features
- User data is stored securely with role-based access controls

---

## Important Rules

- Every seller and rider must be approved before operating
- Admin should verify documents carefully — fraud prevention
- Rejection should include a reason when possible
- Customer data is private — access only for legitimate support needs
- Deactivating a seller or rider stops them from operating immediately

---

## What If Something Goes Wrong?

| Problem                         | What to do                                           |
| ------------------------------- | ---------------------------------------------------- |
| Seller approved by mistake      | Deactivate seller; they stop receiving orders        |
| Rider with fake documents       | Reject or deactivate; investigate                    |
| Customer complaint about seller | Review seller's order history; take action if needed |
| Too few riders in an area       | Recruit more riders; check fleet map for coverage    |
| Seller in wrong location        | Ask seller to update location in profile             |
